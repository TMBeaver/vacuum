# Vacuum 0.3.0 release audit

Verified on this Windows computer on 25 October 2026. Native final checks use the installed current-user `Vacuum.exe`, not a browser preview. The installer-upgrade proof compares the installed payload with the built payload. Earlier development measurements remain in `quality-audit.md`.

Native reports beside this audit contain portable measurements; retained fixtures, detailed logs, prior installed binaries and manifests remain in ignored `test-results/`. For an installed/unpacked build, set `VACUUM_PACKAGED_EXE` before running a verifier. The fresh-install/upgrade verifier refuses an existing product installation and is intended for a clean test account.

The final run passed `node tests/ui.cjs` and these scripts under `scripts/`: `verify-keyboard.cjs`, `verify-display.cjs`, `verify-lifecycle.cjs`, `verify-security-errors.cjs`, `verify-storage.cjs`, `verify-animation.cjs`, `verify-scheduling.cjs`, `verify-browser-cache.cjs`, `verify-large-bin.cjs`, `verify-performance.cjs`, `verify-startup.cjs`, `verify-edited-undo.cjs` and `verify-compression-recovery.cjs`. `final-verification.json` records the exact installer and installed payload hashes. The compression-recovery proof measured 8 MB → 1 MB → 8 MB of allocation with matching SHA-256 values. The 16-second motion pass averaged about 165 requestAnimationFrame callbacks per second on this computer, with a 6.1 ms median callback interval; it observed the actual outward and return movement in a 230-pixel lane.

Verification has practical limits: no real Windows sign-out, reboot or physical monitor reconfiguration was performed. Startup command/approval, hidden startup scheduling, resume listeners and display events were exercised directly. Defender detection effectiveness was not evaluated with malware. Measurements are from this computer; unknown applications cannot be classified as unnecessary solely from age, CPU usage or an open port. The installer is unsigned. These limits are disclosed rather than represented as passing tests.
